# CX Interview Lab

기업별 CX / CS / Service Operations 면접 준비 관리 프로그램입니다. HTML, CSS, Vanilla JavaScript만 사용하며 npm·빌드·데이터베이스·애플리케이션 서버·유료 API·비밀키가 필요하지 않습니다. GitHub Pages에서 정적 파일로 동작합니다. 모든 개인 입력은 현재 브라우저의 localStorage에 저장됩니다.

## 처음 사용할 때

1. 상단/왼쪽 **연습할 기업**에서 기업 또는 **전체 공통 질문 연습**을 선택하세요.
2. 기본 기업은 로앤컴퍼니(CX 매니저)입니다. 제공받은 본 질문 26개·꼬리질문 42개와 원문 답변을 보존했습니다.
3. 기존 버전의 연습 기록이 있으면 **기존 기록 이전** 안내가 먼저 표시됩니다. 아래 이전 설명을 읽고 선택해 주세요.
4. **기업 관리**에서 다른 지원 기업을 등록하고 **질문 관리**에서 공통 질문을 연결하거나 전용 질문을 만드세요.

## 기업별 준비 관리

- **기업 관리 → 새 기업 등록**: 회사명, 지원 직무, 채용공고 전문, 지원 상태, 면접 일정, 메모를 저장합니다.
- 지원 상태: 지원 예정 / 서류 지원 / 면접 예정 / 면접 완료 / 결과 대기 / 종료.
- 일정은 사용자가 입력한 현지 시각 그대로 저장·표시합니다. 시간대 변환이나 알림 발송은 하지 않습니다.
- 기업 선택 시 예상 질문 수, 완료 수, 재연습 수와 진도율을 확인합니다. 기업 관리 목록에서도 기업별 전체 진도율을 비교할 수 있습니다.
- **보관**하면 선택 목록에서 숨기고 모든 자료를 유지합니다. 기업 관리에서 **복원**할 수 있습니다.
- **삭제**는 별도의 확인창을 띄웁니다. 해당 기업 정보·채용공고·일정·메모·전용 질문·공통 질문 연결·회사별 모범답변·연습 기록·면접 복기를 함께 삭제합니다. 공통 질문 원본과 다른 기업의 자료는 유지됩니다. 취소할 수 있으며, 저장 실패 시 삭제를 적용하지 않습니다. 삭제 완료 후에는 되돌릴 수 없으니 먼저 **데이터 백업**을 사용하세요.

## 공통 질문과 회사별 답변

**질문 관리**에 두 영역이 있습니다.

- **공통 질문 라이브러리**: 여러 기업이 공유할 문항, 카테고리, 공통 연습용 기본 답변, 꼬리질문·참고 답변·키워드·중요도·재연습 표시를 관리합니다.
- **선택 기업 질문**: 공통 질문을 기업에 연결하고, 해당 기업에 맞는 모범답변·꼬리질문·참고 답변·키워드·메모·중요도·재연습 여부를 각각 저장합니다. 회사 전용 질문도 등록·수정·삭제합니다.

공통 문항의 본 질문·카테고리는 공유되므로 공통 라이브러리에서 수정하면 연결된 모든 기업에 반영됩니다. 회사별로 작성한 답변은 유지됩니다. 공통 질문을 새 기업에 처음 연결하면 기본 답변을 사용하며, 기업에서 편집해 저장하면 별도 답변이 됩니다. 공통 문항이 바뀌거나 상속받는 기본 답변이 바뀌면 해당 연습 완료 상태를 초기화합니다. 회사별 답변 편집도 해당 기업의 완료·자기 평가·꼬리질문 연습 상태를 초기화하고 작성한 기본 답변은 남깁니다.

초기 26개 중 회사와 무관하게 사용할 수 있는 23개는 공통 라이브러리에 두고, 나머지 3개(지원 이유·서비스 이해·회사 AX 도입)는 로앤컴퍼니 전용으로 분리했습니다. 초기 공통 라이브러리의 답변은 비워 두고, 로앤컴퍼니 이름이 명시된 꼬리질문은 회사별 연결에서만 사용합니다. 제공받은 **원문 답변·꼬리질문·키워드는 모두 로앤컴퍼니 연결에 보존**했습니다. 다른 회사나 공통 연습에서 사용할 답변은 직접 작성해 주세요. 원문에 없던 경력 사실이나 답변을 자동으로 만들지 않습니다.

**연결 해제**는 그 기업의 연결·회사별 답변·해당 연습 기록만 삭제합니다. **공통 질문 삭제**는 원본과 모든 기업의 해당 연결·답변·연습 기록을 삭제하므로 확인창을 주의해서 읽어 주세요.

## 모의 면접

1. 공통 라이브러리 또는 기업을 선택합니다. 기업에서는 **공통 + 전용 / 연결된 공통만 / 회사 전용만**을 선택할 수 있습니다.
2. **무작위 연습 시작**을 누르거나 질문 목록에서 선택합니다. 같은 세션의 무작위 출제는 중복되지 않으며 모두 출제하면 새 세션으로 시작합니다. 범위 전환·새로고침도 새 세션입니다.
3. 답변을 입력하거나 지원 브라우저에서 한국어 음성 입력을 사용합니다. 텍스트와 타이머 경과 시간은 자동 저장됩니다.
4. 타이머의 30·60·90초 표시는 답변 길이 기준이며 자동 종료하지 않습니다.
5. **답변 완료** 후 참고 모범답변·키워드를 보고 **잘함 / 보통 / 다시 연습**으로 자기 평가합니다. AI 분석 기능은 없습니다.
6. **꼬리질문 시작**으로 순서대로 답변합니다. 각 답변을 완료해야 참고 답변을 볼 수 있습니다. 원문에 없는 꼬리질문은 만들지 않으며 빈 경우 버튼을 숨깁니다.
7. **다시 연습할 질문**은 자기 평가가 재연습이거나 질문 관리에서 재연습 표시한 질문만 출제합니다. 수동 재연습 표시는 질문 편집에서 해제합니다.

검색·카테고리 필터는 목록과 무작위 출제에 함께 적용됩니다. 공통 연습 기록과 각 회사의 기록은 같은 문항이라도 독립적입니다. 완료 수는 기본 질문 기준이며 꼬리질문 기록은 별도로 저장합니다. 답변을 수정하면 해당 완료·자기 평가를 다시 해야 합니다.

### 음성 기능

질문 읽기는 SpeechSynthesis, 음성 답변은 Web Speech API를 사용합니다. 브라우저·한국어 음성 설치·마이크 권한에 따라 지원이 다르며 GitHub Pages HTTPS 환경을 권장합니다. 미지원·권한 거부·오류 시 텍스트 입력으로 계속할 수 있습니다. 음성 입력 중 직접 편집하려면 먼저 음성을 중지하세요. 브라우저가 외부 음성 처리 서비스를 사용할 수 있으므로 민감한 정보를 말하지 마세요. 앱 자체는 별도 음성 API나 유료 서비스를 호출하지 않습니다.

## 면접 복기

기업을 선택하고 **면접 복기 → 새 면접 복기**에서 실제 질문, 당시 답변, 아쉬운 점, 개선할 답변을 저장합니다. 이후 수정·삭제할 수 있습니다. **다음 연습 질문으로 등록**에서 해당 기업 전용 또는 공통 라이브러리와 기업 연결 중 선택합니다. 개선 답변이 있어야 등록되며 초기 중요도는 높음, 재연습 표시는 켜짐입니다. 복기를 삭제해도 이미 등록한 연습 질문은 남습니다.

## 기존 기록 이전과 저장 안전성

- 이전 키: `cx-interview-lab:v1`, 새 데이터 키: `cx-interview-lab:v2`.
- v1 기록이 있으면 자동 덮어쓰기 전에 안내합니다. **기존 기록을 로앤컴퍼니로 이전**을 누르면 기본 답변·완료·자기 평가·시간·꼬리질문 기록을 복사합니다. 기존 v1 원본은 삭제하지 않습니다. 기업·질문 삭제 후에도 이 이전 원본 백업은 자동 삭제하지 않으며, 데이터 백업 파일에 포함됩니다.
- **나중에 · 새 기록으로 시작**을 선택하면 현재 창에서 새 기록을 작성할 수 있습니다. 다음 접속 시 이전 안내를 다시 표시하며, 나중에 이전할 때 이미 작성한 v2 기록을 우선하고 나머지 v1 기록을 병합합니다.
- 이전·등록·수정·삭제는 저장이 확인된 뒤 반영합니다. 저장 실패를 화면에 표시하며 관리 폼 입력과 삭제 대상은 유지합니다. 연습 입력이 저장되지 않으면 창을 닫기 전에 답변을 복사하세요.
- 손상된 데이터는 자동 덮어쓰지 않고 저장을 중지합니다. 다른 탭의 변경이 발견되어도 덮어쓰지 않습니다. 답변을 복사하고 백업한 후 원인을 확인하거나 새로고침하세요. 동시에 여러 탭에서 편집하지 않는 것을 권장합니다.
- **데이터 백업**은 v1·v2 저장 원본과 현재 메모리 데이터를 JSON으로 내려받습니다. 현재 자동 복원/가져오기 UI는 없으며 복구 시 이 파일을 개발자에게 전달해 확인할 수 있습니다. 이름·경력·채용정보가 포함될 수 있으니 공개 저장소에 올리지 말고 안전하게 보관하세요.
- 브라우저·기기·접속 주소마다 저장소가 다릅니다. 서버 동기화·로그인·기기 간 공유는 없습니다. 브라우저 데이터 삭제, 비공개 모드 종료 등에 따른 데이터 손실에 대비해 중요한 기록은 백업하세요.

## 파일 구성 및 데이터 수정

- `index.html`, `styles.css`: 기존 면접 화면과 반응형 관리 UI.
- `questions.js`: 제공받은 로앤컴퍼니 원문 26개·꼬리질문 42개. `lawcompany-q01`~`lawcompany-q26` ID를 유지합니다. 각 질문은 `id`, `category`, `question`, `answer`, `followUps`, `keywords`를 사용하며 `notes`는 선택 메모입니다.
- `store.js`: 초기 기업·공통/전용 분류, v2 모델, 기존 기록 이전, 검증·저장.
- `app.js`: 연습, 타이머, 음성, 회사별 기록.
- `manage.js`: 기업·질문·면접 복기 관리, 삭제 확인, 백업.
- `tests/smoke.cjs`, `tests/management.cjs`: 브라우저 자동 검증.

개인 자료는 앱 화면에서 편집하세요. `questions.js`는 새 브라우저의 초기 데이터이며 이미 저장한 v2 자료를 코드 업데이트로 덮어쓰지 않습니다. 초기 공통 분류를 바꾸려면 `store.js`의 `commonNumbers`를 참고하세요. 문항과 답변은 HTML이 아닌 일반 텍스트로 렌더링합니다.

## GitHub Pages 배포

루트의 HTML·CSS·JS 파일을 함께 커밋·푸시한 뒤 GitHub 저장소 **Settings → Pages → Deploy from a branch → main → / (root) → Save**를 선택합니다. 배포가 완료되면 **Visit site**를 누릅니다. npm 설치나 빌드는 필요 없습니다. 상대경로를 사용하여 저장소 하위 경로에서도 동작합니다. 파일 직접 열기도 지원하는 구조이나 브라우저별 저장·음성 제약이 있으므로 Pages HTTPS 이용을 권장합니다.

## 개발자 검증

Node.js, Playwright, Chromium이 있는 개발 환경에서 실행합니다. 앱 사용자에게 이 도구는 필요 없습니다.

```sh
node --check store.js
node --check app.js
node --check manage.js
node tests/smoke.cjs
node tests/management.cjs
```

테스트는 임시 로컬 HTTP 서버와 격리된 브라우저를 사용하고 종료 후 닫습니다. Chromium 경로는 기본 `/usr/bin/chromium`이며 smoke 테스트는 `CHROMIUM_PATH`로 변경할 수 있습니다. Playwright가 공용 도구로 제공되는 환경에서는 필요에 따라 `NODE_PATH`를 지정합니다.

기존 면접 기능·원문 전체 표시·경력 사실, 기업 등록/수정/보관/복원/삭제, 회사별 기록·답변 분리, 공통 연결/해제/수정/삭제, 혼합 출제, 복기 재활용, 이전/이전 연기/이전 실패, 삭제 실패, 손상 데이터와 다중 탭 보호, 백업, 모바일 넘침을 검증합니다. 저장·마이크 오류는 모의 API로 재현합니다. 실제 마이크 품질과 한국어 음성 재생은 지원 기기에서 별도 확인해야 합니다. 개발 환경의 관리 정책으로 `file://` 브라우저 자동 검증은 제한될 수 있습니다.
