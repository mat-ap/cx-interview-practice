# CX Interview Lab

CX / CS / Service Operations 경력직 면접을 한국어로 연습하는 개인용 웹앱입니다. HTML, CSS, Vanilla JavaScript만 사용합니다. npm, 빌드, 데이터베이스, 애플리케이션 서버나 API 키가 필요하지 않습니다.

## 사용 방법

1. `index.html`을 브라우저로 열거나 GitHub Pages에 접속합니다.
2. **무작위 연습 시작** 또는 오른쪽 질문 목록에서 질문을 선택합니다.
3. 타이머를 시작하고 답변을 입력합니다. 30·60·90초 표시는 답변 길이를 가늠하는 기준이며 시간이 지나도 답변을 계속할 수 있습니다.
4. **답변 완료**를 누르면 참고 모범답변과 키워드를 볼 수 있습니다. **잘함 / 보통 / 다시 연습** 중 하나로 자기 평가합니다. AI 평가 기능은 없습니다.
5. **꼬리질문 시작**으로 순서대로 추가 질문에 답합니다. 각 답변 완료 후 해당 참고 답변을 펼칠 수 있습니다. 마지막에는 기본 질문으로 돌아갑니다.
6. 왼쪽 **다시 연습할 질문**에서 재연습 대상으로 평가한 질문만 연습합니다. 카테고리와 검색 조건은 목록과 무작위 출제에 함께 적용됩니다. 빈 카테고리는 필터를 바꾸면 됩니다.

같은 세션에서는 무작위 질문이 중복되지 않습니다. 현재 조건의 질문을 모두 풀면 **새 세션 시작**으로 다시 섞습니다. 새로고침은 새 세션입니다. 질문 목록에서 직접 재선택하는 것은 가능합니다.

답변, 경과 시간, 완료 여부, 자기 평가는 `localStorage`에 저장됩니다. 수정한 답변은 다시 완료하고 평가해야 합니다. 꼬리질문 기록은 각각 따로 저장되며 대시보드 완료 수는 기본 질문 기준입니다. 기기·브라우저·접속 주소가 바뀌면 기록이 공유되지 않습니다. 비공개 모드, 브라우저 데이터 삭제, 저장 공간 제한으로 기록이 사라지거나 저장되지 않을 수 있습니다. 중요한 답변은 별도로 복사하세요. 저장 실패는 화면에 표시됩니다. 민감한 고객 정보는 입력하지 마세요.

### 음성 기능

- 질문 듣기: 브라우저 SpeechSynthesis 사용. 한국어 음성 설치 여부에 따라 지원이 다릅니다.
- 음성 답변: Web Speech API를 제공하는 브라우저에서 한국어 인식 사용. 마이크 권한이 필요하며 GitHub Pages의 HTTPS 환경을 권장합니다. 인식 결과가 확정되면 입력창에 추가됩니다. 인식 중 수동 편집하려면 먼저 음성 입력을 중지하세요.
- 브라우저에 따라 외부 음성 처리 서비스가 사용될 수 있습니다. 앱 자체는 별도 API나 유료 서비스를 호출하지 않습니다. 오프라인에서는 음성인식이 작동하지 않을 수 있습니다.
- 미지원·권한 거부·오류 시 텍스트 입력으로 계속 사용할 수 있습니다.

## 질문 교체 및 추가

`questions.js`의 `window.CX_QUESTIONS` 배열을 수정하세요. 첫 버전은 동작 확인용 예시 5개입니다. 수치나 개인 경력을 실제 사실처럼 가정하지 않은 참고 답변이므로 본인 경험으로 교체하세요.

```js
{
  id: 'unique-01', // 중복되지 않는 고정 ID
  category: '협업',
  question: '다른 부서와 이견을 조율한 경험을 말씀해 주세요.',
  answer: '본인의 실제 경험을 바탕으로 작성할 참고 답변',
  followUps: [ // 1~3개, 순서대로 출제
    { question: '합의에 이르지 못했다면요?', answer: '꼬리질문 참고 답변' }
  ],
  keywords: ['공통 목표', '근거', '합의']
}
```

지원 카테고리: 자기소개, 지원동기, 직무 이해, 성공/실패, 컬처핏, 협업, 실무 상황, AX 자동화. 데이터는 HTML이 아닌 일반 텍스트로 작성하세요. 형식 오류·중복 ID는 제외하고 안내합니다. 내용을 완전히 교체하는 경우 새 ID를 부여하면 기존 기록과 섞이지 않습니다.

## 파일 구성

- `index.html`: 대시보드, 면접 화면, 질문 목록
- `styles.css`: 반응형 화면 및 키보드 포커스 스타일
- `questions.js`: 질문·참고 답변·꼬리질문·키워드
- `app.js`: 출제, 타이머, 저장, 음성, 자기 평가
- `tests/smoke.cjs`: 개발자용 브라우저 기능 테스트(앱 실행에 필요 없음)

## GitHub에 반영하고 Pages로 배포하기

1. 작업 화면에 **변경 사항 / Changes**가 있으면 파일을 검토하고 **커밋 / Commit**을 누른 뒤 **푸시 / Push**를 누릅니다. **PR 만들기 / Create pull request** 방식이면 PR을 만들고 GitHub에서 **Merge pull request**를 눌러 `main`에 합칩니다. 제공되는 버튼 이름은 작업 도구마다 다릅니다.
2. GitHub 저장소에서 `main`의 최상위에 `index.html`, `styles.css`, `questions.js`, `app.js`가 있는지 확인합니다.
3. 저장소의 **Settings → Pages**로 이동합니다.
4. **Build and deployment → Source → Deploy from a branch**를 선택합니다.
5. **Branch: main**, 폴더 **/ (root)**를 선택하고 **Save**를 누릅니다.
6. 배포가 완료되면 Pages 화면의 **Visit site**를 누릅니다. 배포 상태는 **Actions**에서도 확인할 수 있습니다.

상대경로를 사용하므로 저장소 이름이 URL 경로에 포함되어도 작동합니다. 무료 계정의 비공개 저장소 등에서는 GitHub 요금제에 따라 Pages 제공 여부가 다를 수 있습니다.

## 개발자 검증

일반 사용에는 설치가 필요 없습니다. 테스트는 Node.js와 Playwright, Chromium이 있는 개발 환경에서 `node tests/smoke.cjs`로 실행합니다. Playwright가 전역 도구로만 제공되는 환경에서는 `NODE_PATH`를 해당 모듈 경로에 맞춰 지정합니다. 테스트는 로컬 HTTP 서버를 잠시 실행하며 종료 후 닫습니다. 마이크 하드웨어와 실제 한국어 음성 품질은 지원 브라우저에서 별도 확인해야 합니다.

### 이번 구현의 검증 결과

Chromium 브라우저에서 자동 검증 15개 통과: 대시보드, 빈 답변 차단, 타이머, 참고 답변 공개, 자기 평가, 꼬리질문, 저장 후 복원, 재연습·검색·카테고리 필터, 중복 출제 방지, 모바일 가로 넘침, 저장 실패, 손상된 기록, 빈 데이터, 안전한 텍스트 렌더링, 음성 미지원·권한 거부 안내, 실행 오류 확인을 포함합니다. 예외 상황은 브라우저 API를 모의해 재현했습니다.

검증 환경의 관리 정책이 `file://` 접근을 차단하므로 파일 직접 열기 자동 검증은 완료하지 못했습니다. 로컬 HTTP 환경에서 정적 파일을 검증했으며, 실제 마이크 입력·한국어 음성 재생과 GitHub Pages 배포 후 확인은 별도입니다.
